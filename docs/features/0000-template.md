# F-NNN. Feature name

**Topic:** `<topic>` · **Status:** idea | planned | active | done | dropped
**Milestone:** MN · **Related:** ADR NNNN, R-NNN, Q-NNN

## What

What the user can do once this exists. Describe it from the user's side, not the
implementation's — "graph an expression and pan around it", not "add a
QGraphicsView subclass".

## Why

Why it is worth building. If the answer is only "other calculators have it", say
so honestly — that is sometimes a good enough reason, and sometimes not.

## Scope

**In:** what this feature covers.
**Out:** what it deliberately does not, and which feature covers that instead.

Being explicit here is what stops a feature growing without limit.

## Design notes

Sketch, constraints, interfaces affected, which modules change. Not a
specification — enough that someone picking it up does not start from nothing.

## Open questions

Anything undecided that blocks or shapes the work. Cross-link to
`../QUESTIONS.md`; do not settle a real decision quietly here — that is what ADRs
are for.

## Done when

Concrete, checkable conditions. "Graphing works" is not one; "`plot(sin(x))`
renders in the terminal with round-numbered ticks and correct asymptote breaks"
is.
